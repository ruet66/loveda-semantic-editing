# LoveDA 지도 조건 GAN 추가 학습

조원이 GPU 서버에서 학습하고 생성·평가 결과를 돌려줄 수 있도록 만든 패키지입니다. **노트북 하나를 실행하면 설정한 실험 하나만 학습합니다.**

| 실행 파일 | 기본 학습 구성 |
|---|---|
| `01_GAN_부분가리기.ipynb` | 부분 가리기 100% |
| `02_GAN_부분전체혼합.ipynb` | 부분 가리기 80% + 패치 전체 가리기 20% |

두 버전은 같은 Python 코드를 사용합니다. 두 번째 노트북의 `FULL_IMAGE_RATIO`를 바꾸면 비율을 조절할 수 있습니다. 객체 전체 가리기 모드는 이번 버전에 넣지 않았습니다.

## Git으로 받은 다음 실행하는 순서

1. 이 저장소를 clone하거나 **Code → Download ZIP**으로 내려받고 압축을 풉니다. 노트북 두 개만 복사하면 실행되지 않습니다. `.gitignore`가 가중치, 원본 학습 데이터, 실행 결과를 제외합니다.
2. 별도로 전달받은 `1022_weights.zip`을 준비합니다. 서버에서 이 폴더로 이동하여 실행합니다.

   ```bash
   python setup_assets.py --archive /path/to/1022_weights.zip
   ```

   ZIP 내부 파일 이름과 모든 SHA256이 코드의 `bundle_manifest.json`과 일치해야 설치됩니다. `weights/*.pt`를 일반 Git에 추가할 필요가 없습니다. 가중치 ZIP은 저장소 Release 첨부 또는 별도 파일 전달로 공유하면 됩니다. 가중치는 [1022 배포 페이지](https://github.com/ruet66/loveda-semantic-editing/releases/tag/v2026.10.22)에서 내려받으세요.
3. Python 3.10 이상 환경과 Jupyter 커널을 준비하고, 서버에 맞는 **torch와 torchvision 조합**을 먼저 설치합니다. 설치 명령은 [PyTorch 공식 설치 안내](https://pytorch.org/get-started/locally/)에서 선택합니다. 코드가 사용하는 API는 torch 2.4 이상이 필요합니다. 해당 Python 환경을 노트북 커널로 선택하세요. 노트북은 `requirements.txt`의 보조 패키지만 설치합니다.
4. 원하는 노트북 하나를 열어 설정 셀을 수정하고 위에서부터 실행합니다. 학습용 기본값은 `TRAIN=True`이므로 설정 확인 후 실행하세요. 코드 점검 목적으로 열기만 하면 학습하지 않습니다.
5. 결과의 `evaluation/index.html`, `comparison_with_saved_runs/index.html`, `human_review.csv`를 확인하고, 노트북 마지막 셀에서 만든 `RUN_NAME_results.zip`을 전달합니다. 사람의 판정표를 수정한 경우 마지막 ZIP 셀을 다시 실행합니다.

압축 코드 배포본을 받은 경우에도 압축을 푼 뒤 2번부터 같습니다. 설치 도중인 가중치를 실행 중인 학습에 덮어쓰지 마세요.

## 서버 담당자가 바꿀 설정

| 설정 | 의미 |
|---|---|
| `RUN_NAME` | 실험 이름. 설정이나 코드를 바꾸면 새 이름 사용 |
| `GPU_INDEX`, `BATCH_SIZE` | 사용할 GPU와 배치 크기. 메모리가 부족하면 배치 축소 |
| `NUM_TRAIN_IMAGES` | 원본 이미지 수 2~2490 또는 `None`(전체). 과거 평가 원본 32장 제외 |
| `DATA_ROOT` | `Train/Urban`, `Train/Rural`의 상위 경로. `Urban`, `Rural` 바로 위도 지원 |
| `TRAIN_ZIP` | 이미 받은 공식 Train ZIP 경로. 없으면 다운로드 옵션 사용 |
| `DOWNLOAD_TRAIN_IF_NEEDED` | 데이터가 없을 때 공식 ZIP 다운로드 허용. 약 4GB, 여유 공간 20GB 권장 |
| `PATCH_SIZE` | 기본 256. 512는 별도 GPU 메모리 점검 후 사용 |
| `FULL_IMAGE_RATIO` | 선택한 패치의 RGB를 전부 가리는 비율. 의미지도와 정답 RGB는 유지 |
| `BALANCE_STRENGTH` | 실제 가린 클래스 면적 분포를 완만하게 보정. 정확한 균등 보장 아님 |
| `SEED` | 비교 시 같은 정수 사용. `None`이면 새 시드를 뽑아 기록 |
| `TOTAL_UPDATES` | 기본 4000회 추가 반복. AMP에서 실제 G/D 업데이트 횟수는 별도 기록 |
| `RUN_SMOKE_CHECK` | 서버에서 임시 모델로 저장·재개까지 3회 점검. 본실험과 별도 |
| `TRAIN=False` | 본학습 없이 `EVALUATION_CHECKPOINT`로 지정한 모델 생성·평가 |

노트북 초기 점검은 선택한 GPU가 보이는지 확인하여, GPU 설정 오류로 불필요한 데이터 다운로드를 시작하는 일을 막습니다. `DEVICE='cpu'`는 작은 기능 점검에 사용할 수 있지만 본학습에는 GPU를 권장합니다.

`PATCHES_PER_IMAGE`는 계획 주기마다 원본당 생성하는 후보 crop 수입니다. 클래스 보정 때문에 후보의 실제 사용 횟수는 다릅니다. 전체 가리기도 원본 1024 이미지 전체가 아닌 **선택한 패치 전체**입니다.

## 무엇을 학습하고 무엇을 평가하나

기존 `semantic_04000.pt`의 작은 U-Net 생성기와 PatchGAN 판별기를 불러와 새 optimizer로 추가 학습합니다. 외부의 사전학습 이미지 생성 모델을 fine-tuning하는 구성이 아닙니다. 입력은 가린 RGB 3채널 + 의미지도 7채널 + 마스크 1채널입니다. 기존 의미지도 다중 단계 주입, 고정 분할 교사 손실과 질감 손실을 유지합니다. 학습에는 원래 지도와 원래 RGB를 사용합니다.

편집 시에는 수정한 의미지도를 주고 선택 영역을 다시 생성합니다. 원래 지도 복원 오차, 지도를 바꿨을 때 출력 변화, 별도 분할기의 목표 클래스 인식 비율을 각각 기록합니다. **지도 반응이나 분할기 점수는 편집 성공률이 아닙니다.** 형태·경계·자연스러움은 비교 그림과 `human_review.csv`에서 판단해야 합니다. 편집된 정답 RGB는 없습니다.

개발 평가 51개는 기존에 사용한 사례입니다. 별도로 예약한 Val 원본 1107장 풀의 최종 테스트는 기본 꺼져 있고, 사용하려면 공식 Val 데이터가 추가로 필요합니다. 기본 패키지에는 개발 입력만 포함합니다.

두 학습의 원본 집합과 seed를 같게 해도 가림 면적에 따른 클래스 보정으로 실제 crop 순서는 달라질 수 있습니다. 같은 미니배치에서 가림 한 요소만 바꾼 엄밀한 실험으로 해석하면 안 됩니다. GAN 생성 자체는 고정 입력에 대해 결정적입니다.

## 저장·재개와 오류 대응

- `runs/RUN_NAME/STOP` 파일 생성 또는 학습 셀 중단으로 현재 배치 후 저장합니다. 강제 서버 종료 시에는 마지막 저장 이후의 진행을 잃을 수 있습니다.
- 재개하려면 STOP 파일을 확인 후 제거하고 같은 설정에서 `RESUME=True`로 실행합니다. optimizer, AMP scaler, RNG, 계획과 진행 상태를 복원합니다.
- 코드·데이터·설정이 바뀐 상태의 재개는 거부합니다. Git에서 코드를 갱신한 후에는 새 실험 이름을 사용하세요. 학습 중에는 코드나 가중치를 교체하지 마세요.
- 강제 종료 후 잠금이 남으면 해당 프로세스가 종료됐는지 확인한 뒤 `training.lock`을 정리합니다.
- 같은 평가 출력 폴더에 다른 체크포인트나 평가 설정을 덮어쓰는 것은 거부합니다. 추가 학습 뒤 다시 평가하거나 audit/global probe 설정을 바꾸면 기존 평가 폴더를 다른 이름으로 옮기거나 평가 코드의 출력 경로를 새 폴더로 바꾸세요. 수동 판정 CSV도 함께 보관하세요.
- 서버에서 인터넷이 차단되어 있으면 보조 패키지와 공식 Train ZIP을 미리 준비해야 합니다. 네트워크나 디스크 오류는 화면에 표시된 원인을 해결한 뒤 재실행하세요.

## 검토 범위

`검토결과.txt`와 `validation/`에 근거를 담았습니다. 두 노트북의 소규모 실제 실행, 모델 로딩, 가림·저장·재개, 생성·평가·ZIP 출력을 점검했습니다. **4000회 본학습 및 품질 개선 검증은 수행하지 않았습니다.** 기존 중단 실험도 재개하지 않았습니다.

검증은 로컬 Windows CPU 및 RTX 4060 Ti에서 수행했습니다. 조원의 실제 Linux/GPU 환경, 공식 데이터의 신규 전체 다운로드, 512 패치의 backward/메모리는 아직 검증하지 않았습니다. 서버에서 초기 점검과 선택적인 짧은 점검을 통과한 뒤 본학습을 실행하면 됩니다.
